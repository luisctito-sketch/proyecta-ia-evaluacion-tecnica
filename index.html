ETAPA POSTERIOR A LAS PRUEBAS FUNCIONALES

EVALUACIÓN TÉCNICA: ¿qué tan bien funciona el sistema y contra qué referencia puede defenderse?

Este módulo transforma los resultados de las pruebas en indicadores cuantitativos y cualitativos. La evaluación puede aplicarse al sistema completo, a un subsistema, al hardware, al software, al firmware o a un componente/dispositivo específico.

Regla central: ningún resultado se declara “bueno”, “preciso”, “confiable” o “eficiente” sin un criterio de comparación previamente definido y documentado. El criterio puede provenir de una norma, especificación del fabricante, libro técnico, página oficial, modelo matemático, simulación, requerimiento de diseño u otra fuente defendible.
①Definir qué se evalúa

Sistema, subsistema, hardware, software, firmware o dispositivo.

②Elegir indicadores

Solo los pertinentes al objetivo y a la mención.

③Calcular

Errores, estadísticos, confiabilidad, eficiencia, QoS, control, etc.

④Comparar e interpretar

Resultado vs. criterio externo, con una conclusión técnica sustentada.

CONCEPTOS Y FÓRMULAS QUE DEBE RECORDAR EL ESTUDIANTE

Exactitud de medición

Cercanía entre un valor medido y el valor verdadero del mensurando. El VIM advierte que la exactitud no es una magnitud a la que se asigne directamente un valor numérico.

En el proyecto se sustenta mediante errores, incertidumbre y comparación con referencia.

Precisión / repetibilidad

Concordancia entre resultados obtenidos mediante mediciones repetidas bajo condiciones especificadas.

s = √[Σ(xᵢ − x̄)²/(n−1)]

Error absoluto y relativo

e = x − xref    |e| = |x − xref|
e% = |e| / |xref| × 100
Si xref = 0, el error relativo porcentual no debe calcularse de esta manera.

Media y varianza muestral

x̄ = (1/n)Σxᵢ
s² = Σ(xᵢ−x̄)²/(n−1)

MAE y RMSE

MAE = (1/n)Σ|xᵢ−xrefᵢ|
RMSE = √[(1/n)Σ(xᵢ−xrefᵢ)²]

Disponibilidad

A = Top / (Top + Tfuera) × 100
Debe acompañarse del periodo de observación y definición de “falla”.

MTBF y MTTR

MTBF = tiempo operativo / Nº fallas
MTTR = tiempo de reparación / Nº fallas

Eficiencia energética

η = salida útil / entrada × 100
Solo si “salida útil” e “entrada” están físicamente bien definidas. También puede evaluarse consumo energético respecto a una línea base.

Eficacia

Eficacia = resultado alcanzado / objetivo cuantificado × 100
Úsala solo cuando el objetivo tenga una meta numérica comparable.

Productividad

Productividad = salida útil / recurso utilizado
Define claramente cuál es la salida y cuál el recurso: tiempo, energía, memoria, operaciones, etc.

Control automático

Mp% = (ypico − yss)/|yss − y0| × 100

También pueden usarse tiempo de subida, tiempo de establecimiento, error estacionario, IAE, ISE o ITAE según el objetivo.

Telecomunicaciones / QoS

Pérdida% = paquetes perdidos / enviados × 100
Throughput = bits útiles recibidos / tiempo
Exactitud ≠ precisión. Una serie puede ser muy repetible (precisa) y, sin embargo, estar desplazada del valor de referencia. El chatbot revisará que no se utilicen ambos términos como sinónimos.

FUENTE EXTERNA Y CRITERIO DE ACEPTACIÓN

Antes de decidir si el resultado cumple o no cumple, documenta de dónde sale el valor con el que lo compararás.

Norma / recomendación

ISO, IEC, IEEE, ITU, reglamento técnico u otra fuente aplicable.

Fabricante / datasheet

Especificación oficial de sensor, microcontrolador, fuente, transceptor, etc.

Libro / artículo técnico

Modelo, rango o indicador publicado y contextualizado.

Modelo matemático

Valor teórico obtenido de ecuaciones y supuestos claramente declarados.

Simulación

Resultado de MATLAB, Simulink, Proteus u otra herramienta, con parámetros documentados.

Instrumento de referencia

Medición patrón o de mayor desempeño metrológico.

Línea base

Desempeño antes de implementar la solución o sistema convencional comparable.

Requerimiento de diseño

Meta cuantificada y justificada desde los objetivos o especificaciones del proyecto.

No inventes el umbral. Si una fuente solo define el indicador, pero no un límite de aceptación universal, el estudiante debe establecer y justificar su propio criterio de diseño o buscar una fuente que sí corresponda al contexto.

INTERPRETACIÓN OBLIGATORIA DE CADA RESULTADO

Un número aislado no constituye evaluación técnica. Por cada indicador debe existir un texto que explique: qué se calculó, qué valor se obtuvo, con qué se comparó, si cumple y qué implica para el proyecto.

REFERENCIAS TÉCNICAS DE ORIENTACIÓN

Metrología: JCGM 200:2012 (VIM) y Guías JCGM/GUM para conceptos de medición, error e incertidumbre.

Software / firmware / ICT: ISO/IEC 25010:2023 como modelo de calidad del producto ICT/software.

Telecomunicaciones: ITU-T Y.1540 para parámetros de desempeño IP e ITU-T Y.1541 para objetivos/clases de QoS cuando sean aplicables.

Control: métricas de respuesta transitoria como tiempo de subida, tiempo de establecimiento y sobreimpulso; el criterio debe provenir del diseño, modelo, simulación o bibliografía pertinente.

Electromedicina: IEC 60601-1 para seguridad básica y desempeño esencial; IEC 62304 para procesos de software de dispositivo médico; ISO 14971:2019 para gestión de riesgos.

Importante: citar una norma no significa que el prototipo esté certificado. La evaluación académica puede utilizar requisitos o conceptos como referencia, pero la conformidad formal exige el procedimiento completo de la norma y, cuando corresponda, laboratorios y organismos competentes.
